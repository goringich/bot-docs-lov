# Excel export (актуально на 2026-03-14)

Экспорт в Excel строится на основе данных в БД и предназначен для работы админов (закупка/сборка/раздача).

## Реализации

### 1. Бот-экспорт (backend)
- `backend/app/excel_export.py`
- Тесты: `backend/tests/test_excel_export.py` (20 тестов)
- Команды: `/export_items`, `/export_pickup`, `/export_xlsx`

### 2. Операционный экспорт (admin_service, legacy)
- `Orders → 📥 Экспорт заказов` — `GET /orders/export` (4 листа)
- `Orders → 📜 Экспорт истории` — `GET /orders/export-history` (3 листа: история заказов, строки, аудит)
- `Orders → 📄 Экспорт по шаблону` — `GET /orders/export-template` (по `samples/excel/template.xlsx`)

### 3. Комплексный экспорт-конструктор (admin_service, новый)
- Страница **«📥 Экспорт данных»** в навигации (доступна owner + regional_admin)
- `GET /exports/presets` — возвращает каталог доступных листов и готовые шаблоны
- `POST /exports/build` — собирает multi-sheet XLSX из выбранных типов листов

#### Фильтры (per-sheet и глобальные)

Каждый лист поддерживает:
- `catalog_id` — фильтр по каталогу
- `chat_id` — фильтр по чату
- `pickup_place` — фильтр по точке выдачи
- `date_from`, `date_to` — диапазон дат (YYYY-MM-DD)
- `limit` — максимум строк

На фронтенде: глобальные фильтры (каталог, чат, даты) + per-sheet фильтры через кнопку ⚙️.
- точка выдачи (`pickup_place`)
- статус заказа (`status`)
- диапазон дат (`date_from`, `date_to`)
- текстовый поиск (`search`: имя, телефон, точка, текст сообщения)

## Режимы экспорта

Функция экспорта поддерживает `mode`:

- `full` — полный файл с детальными строками и сводками
- `assembly` — файл для сборки: фокус на позициях и агрегировании
- `pickup` — файл для выдачи: фокус на разрезе по точкам
- `template` — **экспорт по шаблону** (`GET /orders/export-template`): загружает `samples/excel/template.xlsx` как базу, заполняет данными заказов. Позволяет использовать кастомное оформление.

### Export by Template

Endpoint: `GET /orders/export-template`

- Берёт `samples/excel/template.xlsx` как базовый файл (шапка, стили, логотип)
- Заполняет данные заказов начиная с первой пустой строки
- Колонки: ID, Имя, Телефон, Точка выдачи, Статус, Дата, Позиции
- Принимает те же фильтры что и основной экспорт

### Export History (audit)

Новый endpoint: `GET /orders/export-history`

Содержимое:
- `orders_history` — полная история заказов (включая `raw_text`, `error_text`, timestamps)
- `lines_history` — полная история строк заказа (включая line status/errors)
- `audit_summary` — свод по статусам заказов и строк

Использование: сверка, расследование инцидентов, сравнение с “ручной конечной таблицей”.

### Query filters для admin export API

Оба admin endpoint-а поддерживают одинаковые query-параметры:

- `GET /orders/export`
- `GET /orders/export-history`

Важно: эти маршруты являются **статическими** и не должны пересекаться с `GET /orders/{order_id}`. Если после деплоя/обновления API экспорт продолжает отдавать `422` с попыткой распарсить `export` как `order_id`, значит запущен старый экземпляр `admin_service` и его нужно перезапустить.

Поддерживаемые параметры:
- `catalog_id`
- `chat_id`
- `pickup_place`
- `status`
- `date_from=YYYY-MM-DD`
- `date_to=YYYY-MM-DD`
- `search`

`date_to` включителен на уровне дня: для даты `2026-03-09` backend выгружает всё до конца этого дня.

## Содержимое листов

Набор листов зависит от режима, структура:

### Лист «Заказы» (режимы: full, pickup)
| Колонка | Описание |
|---------|----------|
| ID | Номер заказа |
| Имя | Имя покупателя |
| Телефон | Телефон |
| Точка выдачи | Pickup place |
| Статус | Emoji-статус (✅ Подтверждён, ⏳ Ожидает, ❌ Отклонён и т.д.) |
| Дата | Форматирована dd.MM.yyyy HH:mm |
| Позиции | Список товаров через запятую |

### Лист «Позиции» (режимы: full, assembly)
| Колонка | Описание |
|---------|----------|
| Заказ # | ID заказа |
| Покупатель | Имя |
| Артикул | SKU |
| Товар | Название |
| Кол-во | Числовое |
| Ед. | Единица измерения |
| Цена | Текст из снапшота |
| Статус строки | Emoji-статус |

### Лист «Сводка товаров» (режимы: full, assembly)
Агрегация по товарам: Артикул, Товар, Общее кол-во, Единица, Кол-во заказов.
Строки с qty > sanity-порогов (`_MAX_SANE_QTY`) исключаются из агрегации.

### Лист «По точкам» (режимы: full, pickup)
Агрегация по точкам выдачи: Точка выдачи, Кол-во заказов, Покупатели (перечень имён).

## Оформление

- **Title row**: объединённая ячейка с названием каталога + датой генерации, синий фон
- **Header row**: синий фон (#4472C4), белый жирный шрифт, center alignment
- **Data rows**: zebra-striping (чередующиеся белый/светло-голубой #F2F7FB)
- **Auto-width**: колонки автоматически подстраиваются под контент (min 10, max 50)
- **Freeze panes**: заморозка строк заголовка для прокрутки
- **Auto-filter**: фильтрация по всем колонкам

## Примечания

- Для воспроизводимости экспорт использует снапшоты в `order_lines` (`item_sku`, `item_title`, `price_text_snapshot`).
- Проблемные строки (`bad_qty/unknown_item/stopped`) как правило не должны попадать в “закупку”, но полезны для аудита.
