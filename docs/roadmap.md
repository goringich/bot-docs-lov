# Roadmap

Назначение: общий план развития проекта. Документ описывает целевые работы и не является описанием фактически реализованной системы.

## Следующие приоритеты

### 3. Улучшение UX для пользователей
- [ ] Команда `/my_orders` — показать все активные заказы пользователя
- [ ] Команда `/cancel_order` — отменить последний заказ
- [ ] Preview заказа перед подтверждением (кнопка "Подтвердить"/"Отменить")
- [ ] Настройка "тихого режима" (бот не пишет в группу, только в ЛС)
- [ ] Поддержка фото/документов в заказах (OCR распознавание не требуется в MVP)

### 4. Расширение админ-панели (web)
- [ ] CRUD каталогов (создание/редактирование товаров через UI)
- [ ] Просмотр и редактирование заказов
- [ ] Dashboard с метриками (кол-во заказов, топ товаров, статус раздачи)
- [ ] История изменений (audit log)
- [ ] Массовые операции (bulk stop/unstop товаров)

### 5. Автоматизация стопов
- [ ] Авто-снятие временных стопов по `stop_until` (фоновая задача)
- [ ] Уведомления админам о скором истечении стопа
- [ ] Стопы по расписанию (например, "каждый понедельник с 10:00")

### 6. Улучшение парсинга
- [ ] Поддержка смешанных единиц: "2 шт по 250гр" → 500гр
- [ ] Распознавание дробных количеств: "1.5 кг", "2,5 шт"
- [ ] Синонимы единиц измерения: "кило" → "кг", "грамм" → "гр"
- [ ] Обучаемые алиасы товаров (ML-подход: user feedback loop)

### 7. Экспорт и отчёты
- [ ] Экспорт в CSV (альтернатива Excel для больших объёмов)
- [ ] Автоматическая отправка экспорта в чат по расписанию
- [ ] Сводка по раздаче: топ покупателей, топ товаров, динамика по дням
- [ ] Интеграция с Google Sheets (автоматическая синхронизация)

## Долгосрочные улучшения

### 8. Мультираздача
- [ ] Поддержка нескольких активных раздач в одном чате (разные каталоги)
- [ ] Переключение между раздачами через команду `/switch_catalog <name>`
- [ ] Архивация старых раздач с сохранением истории

### 9. Аналитика и ML
- [ ] Предсказание спроса по историческим данным
- [ ] Рекомендации для пользователей ("часто берут вместе")
- [ ] Автоматическое определение популярных товаров для промо

### 10. Интеграции
- [ ] Webhook для внешних систем (оповещения при новых заказах)
- [ ] API для мобильного приложения (если потребуется)
- [ ] Интеграция с CRM (синхронизация клиентов)
- [ ] Платёжные системы (если потребуется предоплата)

### 11. Масштабирование
- [ ] Поддержка нескольких воркеров (горизонтальное масштабирование)
- [ ] Redis для кэширования каталогов и профилей
- [ ] Оптимизация SQL-запросов (индексы, denormalization)
- [ ] Миграция на PostgreSQL (если MySQL станет узким местом)

### 12. DevOps и мониторинг
- [ ] CI/CD pipeline (автоматические тесты + деплой)
- [ ] Prometheus + Grafana для метрик
- [ ] Centralized logging (ELK stack или аналог)
- [ ] Автоматические бэкапы БД
- [ ] Blue-green deployment для zero-downtime обновлений

## Критерии готовности (Definition of Done)

Для каждой фичи обязательно:
- ✅ Код реализован и прошёл ревью
- ✅ Добавлены/обновлены тесты (если требуется)
- ✅ Обновлена документация (README, ADR, модель данных)
- ✅ Запись в [[changelog/decisions-log]] с обоснованием решений
- ✅ Проверка на staging окружении
- ✅ Нет критических ошибок в логах после деплоя

---

## Принципы приоритизации

1. **Критические баги** (blocker) → чинятся немедленно
2. **Стабильность и надёжность** → важнее новых фич
3. **UX для пользователей** → приоритет над админскими фичами
4. **Автоматизация** → приоритет над ручными процессами
5. **Масштабируемость** → только когда текущая нагрузка близка к лимитам
