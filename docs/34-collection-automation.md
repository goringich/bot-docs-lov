# Автосбор заказов

> [!important] Бизнес-инвариант
> Сборы идут недельными окнами с понедельника по воскресенье. Цикл может
> повторяться каждую неделю или раз в две недели. По умолчанию новый сбор
> открывается в понедельник в `09:15`, закрывается в воскресенье в `18:00`,
> часовой пояс — `Europe/Moscow`.

## Что автоматизировано

1. В `Настройки → Каталог → Автосбор и отчёты` владелец задаёт:
   - ответственного в Telegram: связанный `@username` либо числовой Telegram ID;
   - один или несколько рабочих чатов;
   - периодичность: `1` или `2` недели;
   - день/время начала и окончания;
   - день и несколько времён напоминаний;
   - время ежедневного отчёта.
2. В неделю перед следующим сбором worker отправляет ответственному несколько
   напоминаний. После появления будущего каталога дальнейшие напоминания для
   этого чата прекращаются.
3. Ответственный публикует полный текст ассортимента в соответствующем рабочем
   чате. Используется существующий подтверждённый admin-post ingress:
   произвольное клиентское сообщение каталог не меняет.
4. Если напоминание относится к будущему циклу, публикация создаёт каталог со
   статусом `scheduled`. Повторные публикации обновляют этот же будущий
   каталог идемпотентно.
5. В момент `opened_at` lifecycle закрывает прежний открытый каталог и
   переводит подготовленный каталог в `open`. В момент `closed_at` intake
   прекращается обычным deadline-механизмом.
6. Один раз в день ответственному отправляется отчёт по настроенным чатам:
   новые заказы за день, общее число заказов активного сбора и число заказов,
   требующих внимания.

## SKU и память каталога

- Для повторяющейся позиции сначала ищется SKU последней версии каталога этого
  чата с тем же ключом памяти.
- Если прежнего SKU нет, создаётся детерминированный SKU из operator-owned
  названия.
- `catalog_item_memory` переносит только подтверждённые aliases и unit.
- Клиентский заказ, unresolved queue и похожее название из другого product
  class не создают и не переопределяют SKU.

## Расписание и ручная настройка

Значения по умолчанию:

| Параметр | Значение |
|---|---|
| Периодичность | каждые 2 недели |
| Начало | понедельник, `09:15` |
| Окончание | воскресенье, `18:00` |
| Напоминания | пятница, `10:00`, `15:00`, `19:00` |
| Ежедневный отчёт | `20:00` |
| Часовой пояс | `Europe/Moscow` |

Для двухнедельного чередования можно задать опорную дату. Уже созданный
`scheduled`-каталог можно вручную поправить в `CatalogsPage`: его
`opened_at/closed_at` остаются каноническим runtime-окном.

## Telegram-ограничение

> [!warning]
> Бот не может начать личный диалог только по произвольному `@username`.
> Ник должен принадлежать активному сотруднику, связанному с `tg_user_id` в
> админке. Пользователь также должен хотя бы один раз открыть бота в личных
> сообщениях. Числовой Telegram ID можно указать напрямую.

## Идемпотентность

- Отправленные reminder/report слоты фиксируются в
  `bot_settings.collection_automation_state`.
- Один worker tick не отправляет один и тот же слот повторно.
- Повтор каталожного сообщения не создаёт дубль каталога или товара.
- Если будущий каталог уже подготовлен, следующие reminder-слоты для него
  пропускаются.
