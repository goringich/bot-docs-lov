# Дозаказы (reorder) — двухрежимная система

## Описание функции

Система поддерживает два режима обработки дополнительных заказов (дозаказов) от одного клиента в одном открытом каталоге:

### Режим 1: Каждый как отдельный (текущий, по умолчанию)
- `merge_reorders = false` в `bot_settings`
- Каждое сообщение клиента → отдельный заказ `Order` в БД
- На UI: заказы показываются в список отдельными строками
- Операционно: просто и предсказуемо, но может быть много строк от одного пользователя

### Режим 2: Объединённые дозаказы (новый)
- `merge_reorders = true` в `bot_settings`  (переключается в sysadmin → Debug)
- Первое сообщение → основной заказ
- Второе/третье/... сообщение → child order с `parent_order_id`, `is_reorder=true`
- На UI: основной заказ с развёрнутым списком дополнительных сообщений
- В просмотре заказа: показатель "(дозаказ №2)" + ссылка на исходное ТГ-сообщение каждого

## Схема БД

Добавлены два поля в таблицу `orders`:

| Поле | Тип | Назначение |
|---|---|---|
| `parent_order_id` | INT, FK nullable | Ссылка на основной заказ (для дозаказов) |
| `is_reorder` | BOOL, default 0 | Флаг: это дозаказ (1) или основной заказ (0) |

**Индексы:**
- `ix_orders_is_reorder` — для быстрого фильтра по дозаказам
- `fk_orders_parent_order_id` — внешний ключ на основной заказ

## Логика работы

### Обнаружение дозаказа (в worker/parser)

При обработке нового заказа проверяется:
```
if merge_reorders == true:
    existing_active = найти активный заказ (
        catalog_id = текущий_каталог,
        tg_user_id = пользователь,
        status in ("active", "partial")
    )
    if existing_active found:
        # Это дозаказ
        new_order.parent_order_id = existing_active.id
        new_order.is_reorder = true
        # Объединить товарные строки в parent_order
        # Обновить totals в parent_order
    else:
        # Первый заказ
        new_order.parent_order_id = null
        new_order.is_reorder = false
```

### Агрегация товаров

При рендере экспорта / отправке заказа на выдачу:
- Если `parent_order_id is not null` → берём товаров из дочерних заказов
- Суммируем количества по SKU
- Показываем источник (исходное ТГ-сообщение) для каждой уникальной строки

## UI/UX

### На странице заказов (OrdersPage)
- Основной заказ показывается как обычно
- Если `is_reorder=true` → отмечается как "(доз. #N)" где N — номер дозаказа в цепочке
- На клик → открывается просмотр

### В модальном окне (OrderDetailModal)
Когда `merge_reorders=true`:
- Заголовок: `"Заказ #123 + 2 дозаказа"` (если есть дочерние)
- Новая вкладка / секция: "Все сообщения"
  - Основной заказ (дата, текст, источник ТГ-сообщения)
  - Дозаказ №2 (дата, текст, источник ТГ-сообщения)
  - Дозаказ №3 (дата, текст, источник ТГ-сообщения)
- Состав заказа: агрегированный (сумма всех товаров)

Когда `merge_reorders=false` (текущий режим):
- UI не изменяется

## Переключение режима

Sysadmin → Debug → Карточка "Заказы: дозаказы (reorder)"
- Toggle: "Объединять дозаказы с исходным заказом"
- Сохраняется в `bot_settings.merge_reorders`
